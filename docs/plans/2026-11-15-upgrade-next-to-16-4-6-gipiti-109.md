# Upgrade Next.js to 16.4.6 (GIPITI-109)

## Goal

Move `next` from 16.2.10 to 16.4.6, the current release of the same major. The 16.4 line carries
the security fixes that `pnpm audit` reports against 16.2.10 (20 advisories, 5 of them critical).
Bump `@playwright/test` with it: `next` 16.4 declares a peer of `^1.51.1`, the lockfile resolved
1.51.0, and that version has an advisory of its own.

No migration guide or codemod applies: the major version does not change.

## Files

- `package.json`: `next` 16.2.10 → 16.4.6 (exact pin, as before); `@playwright/test` ^1.50.1 →
  ^1.65.1.
- `pnpm-lock.yaml`: regenerated by `pnpm install`. Besides `next`, its `@next/*` packages and
  Playwright, it picks up what `next` 16.4.6 depends on (`sharp` 0.35.5 as its own optional
  dependency, `postcss` 8.5.23, `@swc/helpers`).
- `next-env.d.ts`: generated by `next dev`; 16.4 adds the `root-params.d.ts` import.

## Order of work

1. Record the `pnpm audit` baseline.
2. Bump both versions, `pnpm install`.
3. `next build`, lint, typecheck, unit tests.
4. Run the production build and check the behaviour the release notes touch (below).
5. Run the dev server and send a chat message through the UI.

## Risks

- 16.4.6 compresses route handler responses that are not already compressed. The chat stream
  (`POST /api/chat`) and the Markdown responses (`/api/agent-markdown/*`) are route handlers, so a
  buffered or doubly compressed stream would break them. Checked in step 4.
- `proxy.ts` detection and matching changed between 16.2 and 16.4. Checked in step 4: redirects for
  protected pages, 404 for unknown paths, the `Accept: text/markdown` rewrite.
- `next-auth` 5.0.0-beta.25 declares a peer of `next` 14 or 15. The warning is not new (it was
  there on 16.2.10); the `next-auth` upgrade is GIPITI-114.
- The app's own `sharp` stays on 0.34.x while `next` now brings 0.35.5 for image optimisation.
  Aligning them is GIPITI-127.

## Verification

- `pnpm audit`: no advisories for `next` or Playwright after the bump (171 → 150 in total).
- `pnpm exec next build`, `pnpm lint`, `pnpm typecheck`, `pnpm vitest run --exclude ".claude/**"`.
- Production build (`next start`):
  - `/` returns 200 with one `Content-Encoding: gzip`; `/chat` without a session redirects to
    `/login`; an unknown path returns 404;
  - `Accept: text/markdown` on `/models` returns `text/markdown`, compressed once, and the
    compressed and uncompressed bodies are the same size after decoding;
  - `/opengraph-image`, `/robots.txt`, `/.well-known/api-catalog`, `/api/health` return 200;
  - `POST /api/chat` as a signed-in user streams in many chunks over the length of the answer, with
    no `Content-Encoding`.
- Dev server: a message sent through the chat UI gets a streamed answer, no console or server
  errors.
- Playwright E2E is left to CI: it needs the 1.65 browser binaries.
